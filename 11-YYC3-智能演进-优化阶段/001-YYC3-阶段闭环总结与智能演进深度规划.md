### 1.3 三阶段能力地图

**P0 基础完善层** — 解决"可用"问题
- 类型安全：消除 `any`，引入 `BeforeInstallPromptEvent` 类型
- 测试体系：Jest + ts-jest 配置，从 0 到 21 用例
- 可访问性：ARIA 语义、键盘导航、焦点管理
- 断点 CSS 化：`@media` 原生响应替代 JS resize 监听，修复 reducedMotion DOM 同步缺陷
- 性能监控：Web Vitals（LCP/CLS/INP/FCP/TTFB）采集与阈值评级
- 构建性能：移除冲突 babel 配置，恢复 SWC

**P1 体验提升层** — 解决"好用"问题
- 主题扩展：新增赛博朋克/水墨丹青/极地冰川，浅色主题对比度适配
- 手势交互：左右划翻切歌、双指缩放调音量、长按收藏
- PWA 离线：媒体元数据清单 outbox 同步、图片缓存优先、缓存状态查询
- 缺陷修复：PWAProvider 生产环境提前 return 导致安装提示失效

**P2 智能延伸层** — 解决"好智"问题
- 个性化推荐：曝光/互动行为采集、亲和度对数评分、挂载时一次性智能排序
- i18n：中/英/日三语字典与实时切换
- AI 内容标注：可插拔服务接口 + 本地启发式降级 + 缓存 + 焦点标签浮层
- WebXR：immersive-vr/ar 能力探测与沉浸式入口原型

## 2. 当前架构深度评估

### 2.1 架构优势

**2.1.1 状态管理范式统一**
全部领域状态（version / media-space / widget / config / favorites / recommendation / i18n / annotation）均采用 `useSyncExternalStore` + 模块级 store 模式，与 React 19 并发特性兼容，避免 Context 层级穿透，跨模块组合性强。

**2.1.2 可插拔服务抽象**
AnnotationProvider 接口、host-bridge 能力协商、WebXR 会话抽象均体现"接口先行、实现可替换"的设计思想，为后续接入真实服务预留了干净的扩展点。

**2.1.3 零外部依赖可运行**
AI 标注有本地启发式降级、WebXR 无设备时入口隐藏、推荐无历史时用原序、i18n 有中文兜底——所有智能特性在离线/无硬件/无服务环境下均可优雅运行，符合 PWA 离线优先理念。

**2.1.4 质量门禁完整**
typecheck → lint → test（139 用例，覆盖率 92.76%）→ build → E2E（6 关键路径）→ SW 生成形成六道闭环，构建产物静态可部署，CI 可自动发布 Pages。

### 2.2 现存边界与技术债

| 编号 | 边界 | 影响 | 严重度 |
| ---- | ---- | ---- | :---: |
| B-01 | 推荐排序仅挂载时计算，冷启动无历史时无个性化 | 首次体验与老用户体验一致 | 中 |
| B-02 | AI 标注为本地文件名启发式，无语义理解 | 标签质量依赖命名规范 | 中 |
| B-03 | WebXR 仅会话入口，未注入实际 3D 渲染循环 | 沉浸式模式无真实内容 | 中 |
| B-04 | 媒体同步仅元数据，文件二进制留本地 | 跨设备媒体不可达 | 低-中 |
| B-05 | 无服务端，宿主桥接端点默认空 | 多端协同能力未激活 | 中 |
| B-06 | ~~测试均为单元级，无 E2E / 视觉回归~~ **已闭环：Playwright 6 关键路径** | UI 交互回归风险 | 已消除 |
| B-07 | 组件 72 个但无组件市场/插件机制 | 生态扩展受限 | 低 |
| B-08 | i18n 仅覆盖关键 UI，配置面板等仍中文 | 国际化不完整 | 低 |
| B-09 | 性能监控数据仅本地持久化，无上报通道 | 无法聚合分析 | 中 |
| B-10 | 上传媒体存 IndexedDB 无容量管理 | 长期大量上传可能超限 | 低 |

| 风险 | 概率 | 影响 | 缓解策略 |

## 3. 后续演进深度规划

### 3.1 演进原则

后续演进应遵循 YYC³「五高架构」约束：

- **高可用**：任何智能特性不可用时，基础画廊必须照常工作
- **高性能**：新增特性不得阻塞首屏，构建保持静态导出与 SWC
- **高安全**：用户媒体与行为数据本地优先，上报需脱敏
- **高扩展**：接口先行，实现可替换，避免硬编码服务
- **高智能**：从"规则驱动"向"数据驱动"渐进，不做无数据支撑的伪智能

### 3.2 P3 — 真实能力深化（建议 4-8 周）

| 方向 | 目标 | 关键动作 | 验收标准 |
| ---- | ---- | ---- | ---- |
| **AI 标注真实化** | 接入多模态模型 | 配置 `NEXT_PUBLIC_ANNOTATION_ENDPOINT`，服务端调用视觉模型；保留本地降级 | 远程标注命中率 > 90%，失败自动回退 |
| **推荐在线化** | 冷启动也有个性化 | 接入宿主行为 API；增加主题/布局偏好维度；A/B 对比排序效果 | 首屏推荐可解释，停留时长提升可量化 |
| **WebXR 渲染注入** | 沉浸式画廊真可看 | 将 R3F 场景挂载到 XR session 的 `requestAnimationFrame`；支持手柄射线交互 | 头显中可见 3D 画廊并可翻页 |
| **性能数据上报** | 可观测性闭环 | 增加匿名上报端点；LCP/CLS/INP 聚合面板 | 可查看 P75 分位数与趋势 |
| **E2E 测试** | UI 回归防护 | 引入 Playwright，覆盖主题切换/手势/PWA 安装主流程 | 关键路径 E2E 全绿 |

### 3.3 P4 — 数据与运营（建议 2-3 个月）

| 方向 | 目标 | 关键动作 | 验收标准 |
| ---- | ---- | ---- | ---- |
| **内容运营体系** | 作品可管理 | 后台上传/分类/标签编辑；标注结果人工校正回流 | 非技术人员可维护画廊内容 |
| **A/B 实验框架** | 设计决策数据化 | 主题/布局/动效分桶实验；指标采集与显著性检验 | 实验可配置、结果可复现 |
| **i18n 完整化** | 全 UI 多语 | 配置面板/媒体空间/组件文案纳入字典；RTL 预留 | 三语覆盖 > 95% UI 文案 |
| **媒体跨端同步** | 多设备可达 | 二进制分片上传 + 断点续传；容量配额管理 | 上传媒体可跨设备恢复 |
| **无障碍深化** | WCAG 2.1 AA | 色彩对比度审计、屏幕阅读器实测、键盘全流程 | 自动化审计零严重项 |

### 3.4 P5 — 生态与商业化（建议 3-6 个月）

| 方向 | 目标 | 关键动作 | 验收标准 |
| ---- | ---- | ---- | ---- |
| **组件市场插件化** | 生态扩展 | 定义 Widget Manifest 规范；支持第三方组件注册/加载/沙箱 | 可安装至少 3 个第三方组件 |
| **开放 API** | 平台化 | 开放画廊内容与标注 REST API；API Key 鉴权 | 外部系统可读写内容 |
| **多端统一** | 全场景覆盖 | 封装宿主 WebView 桥接 SDK；桌面端 Electron 壳 | 三端体验一致 |
| **私有化部署** | 企业场景 | 容器化部署方案；数据本地化配置 | 一键私有化部署 |
| **品牌主题定制** | 商业化 | 主题白标与 Logo 替换；按客户生成构建 | 支持客户品牌交付 |

## 4. 优先级评估（RICE 模型）

按 Reach（影响面）× Impact（影响程度）× Confidence（置信度）÷ Effort（工作量）估算优先级：

| 演进项 | Reach | Impact | Confidence | Effort(人周) | RICE | 建议阶段 |
| ---- | ----: | ----: | ----: | ----: | ----: | ---- |
| 性能数据上报 | 100 | 2 | 0.9 | 1 | 180 | P3 |
| AI 标注真实化 | 80 | 2 | 0.8 | 2 | 64 | P3 |
| E2E 测试 | 100 | 1 | 0.9 | 2 | 45 | ✅ 已落地（2026-11-20） |
| 推荐在线化 | 70 | 2 | 0.6 | 3 | 28 | P3 |
| i18n 完整化 | 60 | 1 | 0.9 | 2 | 27 | P4 |
| WebXR 渲染注入 | 30 | 3 | 0.5 | 4 | 11 | P4 |
| 组件市场插件化 | 50 | 2 | 0.5 | 6 | 8 | P5 |
| 媒体跨端同步 | 40 | 2 | 0.6 | 5 | 10 | P4 |
| 开放 API | 30 | 2 | 0.5 | 6 | 5 | P5 |

> 结论：**P3 优先落地性能上报与 AI 标注真实化**（高 RICE、低风险），WebXR 渲染注入虽技术领先但置信度与投入比不佳，建议后置到 P4。

## 7. 近期关键决策建议

1. **是否引入服务端？** 当前纯静态架构是优势，建议 P3/P4 阶段保持静态导出，通过宿主桥接与第三方 BaaS 满足后端需求，避免自建服务破坏高可用与部署简洁性。

2. **AI 标注走本地还是云端？** 建议**混合策略**：云端为主（语义准确），本地为备（离线可用），接口已抽象好，切换成本极低。

3. **WebXR 投入时机？** 建议**不早于 P4**，除非有明确设备与场景需求。当前原型入口已展示能力，保持低成本占位即可。

4. **测试重心？** 48 个单元测试已覆盖核心逻辑，下一步优先补 **E2E 关键路径** 而非堆叠单元测试，边际收益更高。

## 8. 结语

YYC³ Infinite Gallery 已在四个阶段内从「功能原型」演进为「具备完整质量门禁、智能特性可插拔、离线可运行」的成熟前端系统。P0/P1/P2 三阶段闭环验证了团队「分析—落地—验证—归档」的工程节奏可持续。

后续演进的核心命题从「功能建设」转向「数据闭环与生态扩展」：让智能特性从"可运行"走向"可度量"，让内容从"静态展示"走向"可运营"，让架构从"单体应用"走向"开放平台"。建议严格按 RICE 优先级推进，保持五高架构约束，避免为技术炫技牺牲稳定性与简洁性。
