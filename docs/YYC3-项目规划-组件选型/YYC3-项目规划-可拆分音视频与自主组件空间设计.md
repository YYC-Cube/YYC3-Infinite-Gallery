# YYC³ 可拆分音视频与自主组件空间设计

## 📋 文档说明

本文定义音乐与视频播放器拆分合并、多实例独立控制、横竖屏自适应、自定义背景、页面小组件，以及移动端、Web、PWA 与宿主机协同的整体设计。

设计核心：**播放实例与窗口视图分离，组件配置与设备布局分离，宿主机统一承担权威存储与网络访问。**

“独”代表每个实例拥有完整、专有、可配置的空间，而非削减功能、视听、动效或氛围能力；空间预设围绕“宁静致远 · 活力空间”展开。

## 一、现状与设计切入点

项目已有以下可复用基础：

- `components/FloatingMediaPlayer.tsx`：悬浮、拖拽、缩放、播放列表和 Pointer Events。
- `components/ConfigPanel.tsx`：设置面板和背景上传交互。
- `lib/media-db.ts`：IndexedDB 媒体文件持久化。
- `lib/media-store.ts`：媒体映射与播放器布局类型。
- `components/ui/resizable.tsx`：停靠分栏能力。

当前主要限制是：音视频共用当前曲目、播放状态和音量，切换媒体类型会暂停另一方；播放核心与窗口视图耦合。因此不建议继续在原单体组件内叠加功能，而应进行分层改造。

## 二、总体架构

系统分为五层：

1. **媒体运行时层**
   - 管理真实 `HTMLMediaElement`、开源播放器引擎、解码和播放事件。
   - 生命周期只跟随 `sessionId`，不跟随窗口拆分、合并或皮肤切换。
2. **播放实例层**
   - 每个音频或视频实例拥有独立队列、进度、音量、循环、倍速、字幕和后台策略。
   - 多开就是创建多个实例，不复制全局状态。
3. **工作区视图层**
   - 负责统一界面、独立浮窗、合并分组、迷你形态、皮肤和背景。
   - 通过 Portal 或稳定视图画槽移动界面，不重新加载媒体源。
4. **组件与资源层**
   - 统一管理天气、时钟、播放器等小组件。
   - 统一解析 `assetId → 媒体文件/背景/封面`，复用上传与映射能力。
5. **宿主与同步层**
   - 宿主机提供数据库、文件存储、网络代理、同步和版本协商。
   - Web、PWA、移动端只保留离线缓存和待同步队列，不形成第二套权威数据。

## 三、播放器系统设计

### 3.1 独立状态模型

每个播放器实例至少包含以下四类状态：

| 状态类别 | 内容                                              | 生命周期         |
| -------- | ------------------------------------------------- | ---------------- |
| 播放会话 | 队列、当前曲目、进度、播放/暂停、倍速、循环、随机 | 跟随 `sessionId` |
| 独立控制 | 音量、静音、字幕、音轨、画面填充策略              | 每个实例独立     |
| 外观配置 | 引擎、皮肤、背景、透明度、动效、控制栏密度        | 跟随实例并持久化 |
| 窗口布局 | 位置、尺寸、分组、停靠、层级、迷你形状            | 按设备分别保存   |

关键约束：

- 音频和视频不再共用 `currentIndex/isPlaying/currentTime/volume`。
- 统一界面只是将多个实例放入同一个 `groupId`，不是合并它们的播放状态。
- 视频实例之间只共享不可变资源缓存，不共享控制器、事件订阅和媒体元素。
- 删除资源时采用引用计数，避免一个实例释放资源导致其他实例失效。

### 3.2 拆分与合并流程

拆分或合并按以下事务执行：

1. 保存操作前布局，支持撤销。
2. 仅修改 `groupId`、窗口模式和视图画槽。
3. 保持 `sessionId`、媒体元素、引擎实例及事件订阅不变。
4. 将视图移动至独立浮窗或统一容器。
5. 提交新布局；失败则恢复旧布局，不触碰播放状态。

必须保留当前曲目、队列顺序、播放进度、播放/暂停、音量、静音、倍速、循环、随机、字幕、音轨、全屏前尺寸、当前页签、播放列表滚动位置、实例背景、皮肤和迷你形状。

拆分不会自动启动另一个播放器。例如原视频处于暂停状态，拆分后仍保持暂停，避免突然出声。

窗口边界：

- 应用内独立浮窗：保证无重建、无进度丢失。
- 真实浏览器 Popup：作为增强能力；被浏览器拦截时回退为应用内浮窗。跨浏览器文档迁移可以恢复全部控制状态，但部分浏览器可能出现短暂重新缓冲，不承诺跨文档的零中断解码。

### 3.3 横竖屏视频自适应

视频尺寸以媒体元数据 `videoWidth/videoHeight` 为准，而不是以窗口方向猜测：

- 视频内容始终使用 `object-fit: contain`。
- 根据源比例设置 `aspect-ratio`，禁止拉伸和默认裁切。
- 空间不足时使用背景色或实例背景填充留白区域。
- 横屏视频可采用宽控制台；竖屏视频采用上方画面、下方控制栏。
- 使用 `ResizeObserver` 响应容器变化，使用 `orientationchange` 和视口监听处理旋转。
- 旋转只调整 CSS 布局，不重新设置 `src`，不重置播放进度。
- 用户主动选择全屏后，才尝试方向锁定；不支持时保持系统方向。

### 3.4 多开与独立控制

每个视频实例拥有独立媒体元素和控制器，因此可以分别播放不同视频、调节音量、静音和倍速、拖动进度、切换字幕、独立全屏、迷你化或更换背景。

资源保护机制：

- 默认不自动播放新实例，必须由用户手势触发。
- 桌面端根据解码能力设置软上限，达到上限时提示暂停部分实例或降低清晰度。
- 移动端允许多实例存在，但可同时解码数量受系统能力限制；不能解码时保留状态并明确提示。
- 页面隐藏、系统音频焦点和浏览器自动播放策略只影响对应实例，不擅自修改其他实例音量。
- 可提供“全部暂停”作为显式工作区命令，但不作为默认联动行为。

### 3.5 开源播放器与多款形态

通过统一媒体适配层隔离引擎差异。当前 Web/PWA 基线已经落地以下组合：

| 方案                    | 当前用途                                                     |
| ----------------------- | ------------------------------------------------------------ |
| 原生 HTML5 Audio        | 音乐实例、独立音量、进度与队列                               |
| ArtPlayer 5.4           | 视频实例渲染、多开、切源、画中画与容器全屏                   |
| 自定义播放器控制层      | 标准、沉浸、极简、唱机等形态，避免引擎内置控件与项目 UI 冲突 |
| Video.js 10             | 后续可选升级适配器，不作为当前构建依赖                       |
| Media Chrome            | 后续完全自定义控制条的可选路线                               |
| `hls.js` / Shaka Player | HLS、DASH 等流媒体按需扩展                                   |

实施决策：多视频实例需要稳定的实例级生命周期和自定义控制，因此当前采用 ArtPlayer；其默认控制 UI 隐藏，播放、暂停、进度、音量、方向和 PiP 由 YYC³ 会话层驱动。后续可在同一适配接口下评估 Video.js 10，不需要改变窗口与状态模型。

截至 2026-11-19，Vidstack 仍处于仅安全修复维护阶段，Plyr 不再作为新项目首选，二者仅保留为存量迁移参考。

引擎与外观分离，用户可以选择：

- **标准控制台**：完整队列和精确控制。
- **沉浸影院**：画面优先，控制栏自动收起。
- **迷你唱机**：封面、频谱与精简控制。
- **竖屏卡片**：适合移动端和竖屏视频。

精简形态只改变信息排布，完整功能仍可通过展开或更多菜单访问。运行中更换引擎时先保存会话快照，再恢复进度与控制状态；拆分、合并本身不触发引擎切换。引入依赖前需复核版本、许可证及包体影响。

### 3.6 自定义背景与空间氛围

在现有设置面板增加“播放器与组件空间”配置：

- 支持工作区默认背景和实例专有背景；实例未设置时继承工作区背景。
- 背景配置包括图片、透明度、模糊、遮罩、位置和动效强度。
- 上传后生成 `assetId`，实例仅保存资源引用，不保存 Data URL。
- 复用现有上传入口和映射思路，但文件本体改存宿主 Blob 存储，离线时进入 IndexedDB/原生缓存。
- 校验真实 MIME、大小和解码结果，失败时不覆盖旧背景。

空间预设：

- **宁静致远**：低干扰背景、柔和动效、默认不自动出声。
- **活力空间**：可启用频谱、封面律动和鲜明主题。
- 两种预设具有相同播放能力，并遵循系统“减少动态效果”设置。

## 四、页面组件管理与预设小组件

### 4.1 首批组件清单

| 组件       | 数据来源                                         | 刷新机制                             |
| ---------- | ------------------------------------------------ | ------------------------------------ |
| 时钟       | 设备时间、用户选择的时区                         | 可见时每秒；后台停止，恢复时校准     |
| 日历       | 本地日期及实例配置                               | 每分钟、跨日和页面恢复时刷新         |
| 天气       | 宿主机代理的天气服务；手动城市或授权后的粗略定位 | 可见且在线时每 15 分钟；支持手动刷新 |
| 音乐播放器 | 内置、本地上传及宿主媒体库                       | 媒体事件驱动，不轮询                 |
| 视频播放器 | 同上，每个实例独立选源                           | 媒体事件驱动                         |
| 快速笔记   | 宿主文档存储，离线写入待同步队列                 | 编辑事件驱动                         |
| 宿主状态   | 健康检查与能力接口                               | 在线时每 30 秒，断网事件立即更新     |

天气供应商和密钥仅保存在宿主机；定位必须单独授权，拒绝授权时回退到手动城市。

### 4.2 启用、禁用与持久化

设置面板提供组件目录，每个已启用组件生成唯一 `widgetInstanceId`：

- **启用**：创建实例、应用默认配置并分配安全初始位置。
- **禁用**：移除页面视图但保留配置，允许重新启用。
- **删除**：删除实例及布局，资源只有在无其他引用时才清理。
- **配置项**：组件类型、天气城市、时区、皮肤、背景等按工作区保存。
- **布局**：位置、尺寸、层级和形状按设备保存，避免手机布局覆盖桌面布局。
- **资源文件**：统一进入宿主 Blob 存储。

配置修改立即提交；拖拽过程只更新预览，在释放指针后一次性保存。离线时进入待同步队列，界面明确显示“仅本机待同步”，不能静默提示成功。

### 4.3 拖拽、缩放与冲突处理

桌面端：

- 标题栏拖拽，八方向缩放手柄；默认 8px 网格吸附，可临时关闭吸附。
- 使用 Pointer Capture，保证指针移出窗口后仍能完成操作。
- 自由浮窗允许重叠，点击后提升层级。
- 停靠网格不允许重叠：优先移动后续组件寻找空位，无空位则回退并显示冲突预览。
- 缩放受组件最小/最大尺寸约束，视频画面仍保持原始比例。

移动端：

- 默认采用纵向堆叠、底部抽屉和全屏，不使用小屏自由重叠窗口。
- 长按或进入“布局编辑”后拖拽，避免与页面滚动手势冲突。
- 适配 `safe-area`、动态视口和横竖屏切换。

保存冲突：

- 布局记录携带宿主版本号，采用乐观并发控制。
- 同一设备多个标签页通过 BroadcastChannel 通知布局变化。
- 发现过期版本时提供“加载最新布局”或“另存为布局副本”，不静默覆盖。
- 不同设备默认不存在布局冲突。

### 4.4 缩小后的形状与切换

组件支持三种尺寸状态：

1. **展开**：完整功能。
2. **紧凑**：核心信息与常用操作。
3. **迷你**：只显示图形入口和关键状态。

迷你形状包括圆形、圆角方形、横向胶囊和竖向胶囊。并非所有形状都强行适用于所有组件：视频推荐圆角方形，音乐支持圆形唱机，时钟支持圆形或胶囊，天气支持圆角方形或胶囊。

形状仅改变容器与信息排布，不销毁实例、不清空配置、不改变播放状态。单击展开，拖拽空白区域移动，长按或右键打开形状菜单。

### 4.5 与现有页面兼容及异常隔离

- 建立统一层级令牌，替代页面中分散的固定层级值。
- 画廊保持背景层；组件工作区位于其上；设置面板始终处于最高交互层。
- 为页脚、设置按钮和系统安全区预留空间。
- 每个组件拥有独立 Error Boundary，天气失败不会影响播放器或画廊。
- 数据不可用时保留上一次结果并标注时间；无缓存时显示空状态和重试入口。
- 存储配额不足时停止新增上传，旧数据保持可读，并提供清理入口。
- 视频解码失败只暂停对应实例，保留进度，可切换兼容引擎重试。

## 五、Web、PWA、移动端与宿主机架构

### 5.1 三端差异

| 端     | 适配要求                                                                               |
| ------ | -------------------------------------------------------------------------------------- |
| Web    | 键鼠、快捷键、自由浮窗、多栏布局、Popup 增强、无障碍操作                               |
| PWA    | 复用 Web 业务代码，增加安装、Service Worker、离线缓存和媒体会话能力                    |
| 移动端 | 原生壳或 WebView、安全区、触摸布局、底部抽屉、系统媒体控制、后台音频权限和严格解码预算 |

共享播放核心、组件注册表、数据模型和同步协议；仅窗口管理、系统能力和交互层分端实现。

### 5.2 宿主机能力边界

宿主提供版本化 HTTPS 接口：

| 能力       | 调用方式与边界                                           |
| ---------- | -------------------------------------------------------- |
| 能力协商   | 返回宿主版本、支持功能、配额及同步状态                   |
| 元数据存储 | 文档读写、条件版本更新、事务和变更游标                   |
| 文件存储   | 分片上传、下载、哈希校验、引用计数、Range/206            |
| 网络代理   | 仅访问允许列表中的服务，限制超时、重定向、响应大小       |
| 同步       | 增量变更拉取；WebSocket 仅用于变更通知，断开后可轮询补偿 |
| 健康检查   | 在线、降级、维护及版本不兼容状态                         |

Web/PWA 通过 HTTPS 调用；移动端可通过原生网络插件调用同一协议。访问令牌不写入静态包或日志，天气密钥等只能保存在宿主侧。网络代理不能成为任意 URL 转发器，以避免内网探测和 SSRF 风险。

### 5.3 统一存储与同步

宿主侧建议采用：

- SQLite：工作区、组件配置、播放列表、设备布局、变更日志。
- 文件系统或对象存储：媒体、背景和封面。
- 内容哈希：文件去重与完整性校验。
- Tombstone：记录删除，防止旧设备把已删除数据同步回来。

同步规则：

- 配置与资源以宿主为权威，客户端缓存只用于离线和加速。
- 每次写入携带版本号，冲突返回 `409` 后执行合并。
- 设备布局按设备隔离；普通单值配置可按字段合并。
- 播放列表和笔记不直接最后写入覆盖，冲突时保留副本或进行操作级合并。
- 高频播放进度不实时广播；本地节流快照，暂停、结束和页面隐藏时提交。
- 跨端续播作为可选功能，默认不自动在另一设备开始播放。

### 5.4 PWA 离线与缓存

当前项目已有 PWA 文件骨架，但 Service Worker 注册、预缓存路径和匹配规则尚未闭合，实施时应先修复。

目标缓存策略：

- 应用壳和版本化静态资源：Cache First。
- 非哈希静态资源：Stale While Revalidate。
- 宿主配置：Network First，失败读取本地快照。
- 天气：Network First，失败显示带更新时间的旧数据。
- 媒体流：默认不自动缓存，避免大文件迅速占满配额。
- 用户明确选择“离线可用”的媒体才完整下载，并校验配额和哈希。
- 不把不完整的 `206` 响应当作完整文件缓存，离线 Range 请求需由完整缓存正确切片。
- Service Worker 更新不在播放中强制刷新，提示用户在合适时机重启。

### 5.5 宿主机不可用时的降级

统一呈现“在线 / 离线缓存 / 待同步 / 服务不兼容”状态：

- 时钟、日历和已缓存组件继续工作。
- 已缓存的媒体、背景和笔记可读取。
- 配置修改与上传进入持久化待同步队列。
- 未缓存的远程媒体不能伪造可播放状态。
- 天气显示旧数据及时间，无缓存则显示不可用。
- 使用指数退避和抖动重连，写请求携带幂等键。
- PWA 和移动端可离线启动；普通 Web 若从未加载且无缓存，只能展示浏览器无法启动的提示。

## 六、版本管理与发布

- 共享核心、Web、PWA、移动壳和宿主 API 分别带版本号。
- 数据 Schema 使用显式迁移版本，升级前备份，禁止无迁移覆盖。
- 宿主保持当前及前一个主版本的协议兼容，客户端启动时进行能力协商。
- Web/PWA 采用原子静态发布，可快速回滚；Service Worker 与静态资源版本保持一致。
- 移动端按应用商店发布；仅对符合平台策略的 Web 内容使用热更新。
- 播放器引擎和小组件均声明兼容版本，升级失败时回退到原生引擎或上一组件版本。
- 发布流程至少包含类型检查、状态迁移测试、离线测试、媒体 Range 测试和多端兼容验证。

## 七、实施顺序与验收重点

### 7.1 实施顺序

1. 抽取媒体运行时和独立会话 Store，迁移现有播放器。
2. 实现音频/视频独立控制、多视频实例及横竖屏适配。
3. 实现工作区分组、拆分合并、皮肤和实例背景。
4. 建立组件注册表、设置面板、拖拽缩放与布局持久化。
5. 接入宿主存储、网络与同步，再完成 PWA 和移动适配。

### 7.2 核心验收

- 播放中反复拆分、合并，媒体元素不重建、不重新加载、进度不回退。
- 同时运行多个视频和一个音频，各自音量、进度和暂停操作互不影响。
- 横竖屏视频均无拉伸、无默认裁切，旋转不重置播放。
- 禁用、刷新、离线和重新启用组件后，配置与设备布局正确恢复。
- 恢复播放实例时不违反浏览器自动播放策略，不突然出声。
- 宿主断开后无静默丢数据；恢复后待同步操作不重复执行。
- 单个组件、媒体或上传失败不会导致整个画廊工作区崩溃。
