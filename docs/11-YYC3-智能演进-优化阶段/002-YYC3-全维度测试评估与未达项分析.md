### 3.2 性能反模式扫描（dev-expert-pro 方法论）
| 反模式 | 扫描结果 | 判定 |
| ---- | ---- | ---- |
| N+1 查询/API | 无数据库；循环内无 fetch | 🟢 |
| 同步阻塞 I/O | 无 readFileSync 于热路径 | 🟢 |

## 4. 技术战略三栏法（dev-expert-pro）

### 4.1 路线图

| 栏位 | 条目 | 事实锚点 / 启动条件 |
| ---- | ---- | ---- |
| **现在做** | D-01 补 host-bridge 测试 | 覆盖率 18.75% 已实测，阻塞宿主 API 接入 |
| **现在做** | D-03 建立性能基线 | WebGL 首屏无量化数据，优化无依据 |
| **现在做** | 开发者文档图标架构展示 | 本轮评估发现文档缺可视化架构（D-11） |
| ~~**下一步**~~ ✅ 已完成 | D-02 引入 E2E | 已落地：Playwright 6 关键路径，CI 独立 Job |
| **下一步** | D-05 AI 标注真实化 | 触发条件：视觉模型端点可用且标注准确率要求 > 90% |
| **下一步** | D-06 媒体跨端同步 | 触发条件：跨设备恢复需求出现 ≥ 3 用户 |
| **明确不做** | 自建后端服务 | 理由：静态导出是核心优势，隐藏复杂度；重评估条件：需要多用户协作且 BaaS 无法满足 |
| **明确不做** | WebXR 渲染循环投入 | 理由：无设备无场景（未来时信号）；重评估条件：明确 XR 设备 + 展览场景落地 |

### 4.2 偿还节奏
每期预留 20% 工程容量偿还技术债；安全/合规类无配额上限。本期偿还：D-09（host-bridge 测试）为优先级最高。

## 5. 后续规划建议（技能指导综合）

1. **度量先行**：按 dev-expert-pro「无基线不声称提升」，先补性能 benchmark 与覆盖率基线，再谈优化。
2. **测试金字塔补齐**：单元测试已达 48 项，下一步补 E2E 关键路径（主题切换/手势/PWA 安装），边际收益高于继续堆单元测试。
3. **债务常态偿还**：按 20% 配额处理 D-01/D-08/D-09，避免堆积到专项治理。
4. **平台化克制**：按「三条件同时满足才做」判断，当前组件市场（D-07/P5）不满足重复需求与收益可量化条件，维持「明确不做」。
5. **Node 版本升级**：将 CI `NODE_VERSION` 从 20 升至 22 LTS，消除 GitHub Actions warning（低风险高收益）。

## 6. 结语

**实况更新**：全维度评估的 4 项未达（覆盖率、host-bridge、E2E、性能基线）已全部闭环。项目现处于**功能、度量、验证三位一体的稳态**（CI 四 Job 全绿、139 单元 + 6 E2E、覆盖率 92.76%、性能基线建立、0 漏洞）。

剩余 4 项 open 债务（D-04~D-07）均为触发条件未满足的外部依赖——WebXR 设备、AI 标注端点、跨端需求、海外反馈。依据 dev-expert-pro「写不出启动条件的下一步一律移入明确不做」原则，保持观察不提前投入。下一步以「可判定条件」驱动演进，避免为技术炫技牺牲稳定性与简洁性，持续巩固五高架构。
