## 2. 逐项闭环明细

### 2.1 类别 A — 覆盖率补齐

**落地内容**
- 新增 `lib/__tests__/host-bridge.test.ts`：13 用例，覆盖 direct/online/offline/incompatible 四种连接态、hostFetch 代理透传、storage 读写、outbox 入队与 flush、订阅通知
- 新增 `lib/__tests__/core-stores.test.ts`：12 用例，覆盖 config 持久化/DOM 映射、widget 启停/形状/笔记/最小化/订阅、media 图源与布局往返
- 新增测试基建：jsdom 下 `AbortSignal.timeout` polyfill

**过程中发现并修复的真实缺陷**（非仅为测试）：
1. **运行时端点不生效**：`configureHostEndpoint()` 修改 `state.endpoint`，但 `probeHost/hostFetch/hostStorage*/flushOutbox` 全部使用模块加载时的 `ENDPOINT` 常量判断，导致运行时配置形同虚设。引入 `getEndpoint()` 统一读取有效端点修复。
2. **隐式副作用**：`configureHostEndpoint()` 总是触发 `probeHost()`，增加可选参数 `autoProbe = true`，使调用方可控，消除测试与调用竞态。
3. **清空端点能力缺失**：原实现空字符串直接 return，无法重置为直连模式；现支持清空。

**覆盖率实测对比**

### 2.2 类别 B — 性能基线

**落地内容**
- 新增 `scripts/benchmark.mjs` + `pnpm benchmark` 脚本
- 方法论：每基准 3 轮 × 20,000 次，取中位数与 P95，记录完整环境（OS/架构/vCPU/内存/Node 版本）
- 被测函数与 lib 实现保持一致，避免引入 TS 运行时依赖

**实测基线**（环境：darwin 27.2.0 · arm64 · 16 vCPU · 128GB · Node v22.22.3）

| 基准 | 中位数(μs/次) | P95(μs/次) |
| ---- | ----: | ----: |
| affinityScore（亲和度评分） | 0.047 | 0.091 |
| recommendOrder（12 图排序） | 0.434 | 0.513 |
| clamp（窗口边界计算） | 0.003 | 0.026 |
| queue.find（30 曲目查找） | 0.094 | 0.130 |

> 结论：核心计算路径均为亚微秒级，无性能瓶颈。依据 dev-expert-pro「无实测基线不得声称提升」铁律，后续优化须以此表为对照基线。

### 2.3 类别 C — CI 质量

- `.github/workflows/deploy.yml`：`NODE_VERSION` 20 → **22 LTS**，项目代码运行于 22
- CI 实测：`44683187584` **success** — Quality Gate 37s / Build 38s / Deploy 10s
- **注意**：日志仍显示 "Node.js 20 is deprecated" 告警，该告警来自 GitHub Actions 平台自身的 action runtime（checkout@v4 / setup-node@v4 等由 runner 用 Node 20 执行），与项目 `NODE_VERSION` 无关，属平台级已知提示，不影响构建与部署。
